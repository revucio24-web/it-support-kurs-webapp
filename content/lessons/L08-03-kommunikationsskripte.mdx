# Modul 8 – Lektion 3: Kommunikationsskripte und User-Führung

## 1. Lernziele
- Du kannst Kommunikationsskripte für typische Support-Situationen anwenden.
- Du kannst User durch technische Schritte führen.
- Du kannst schwierige Situationen (frustrierte User, Sprachbarrieren) meistern.
- Du kannst professionell und empathisch kommunizieren.

## 2. Theorie kompakt

**Kommunikationsskripte (Templates):**

**1. Begrüßung:**
" Guten Tag, hier ist [Name] vom IT-Support. Wie kann ich Ihnen helfen?"

**2. Identitätsprüfung:**
"Zur Sicherheit: Können Sie mir Ihren Namen, Ihre Abteilung und ggf. Ihre Mitarbeiter-ID nennen? Ich rufe Sie gerne auf Ihrer bekannten Nummer zurück."

**3. Informationen erfragen:**
"Können Sie mir beschreiben, was genau passiert? Seit wann? Gibt es eine Fehlermeldung? Können Sie mir die Fehlermeldung vorlesen?"

**4. Lösung erklären:**
"Ich werde jetzt folgende Schritte durchführen: [Schritt 1], [Schritt 2]. Das kann X Minuten dauern. Ist das für Sie in Ordnung?"

**5. User durch Schritte führen:**
"Klicken Sie bitte auf das Windows-Symbol unten links. Tippen Sie 'cmd' ein. Klicken Sie mit der rechten Maustaste auf 'Eingabeaufforderung' und wählen Sie 'Als Administrator ausführen'. Was sehen Sie?"

**6. Verifikation:**
"Funktioniert es jetzt? Können Sie [Aktion] durchführen und mir sagen, was passiert?"

**7. Abschluss:**
"Das Problem ist gelöst. Ich habe alles dokumentiert. Ihre Ticket-Nummer ist [X]. Bei weiteren Fragen erreichen Sie uns unter [Kontakt]. Schönen Tag noch!"

**User-Führung (Guiding):**
- **Schritt-für-Schritt:** Nicht zu viele Anweisungen auf einmal.
- **Bestätigen:** "Haben Sie das gesehen? Was steht auf Ihrem Bildschirm?"
- **Pausen:** User Zeit geben, Schritte auszuführen.
- **Einfache Sprache:** Kein Jargon.
- **Geduld:** Nicht hetzen; User kann langsamer sein.

**Schwierige Situationen:**

| Situation | Technik |
|---|---|
| Frustrierter User | Empathie ("Ich verstehe Ihre Frustration"); Lösungsorientiert; nicht persönlich nehmen |
| Sprachbarriere | Einfache Sprache; Screenshots/Remote-Support; Übersetzungstool |
| User kann nicht beschreiben | Remote-Support nutzen ("Zeigen Sie mir, was passiert") |
| User ist ungeduldig | Zeitrahmen nennen ("Das dauert ca. 5 Minuten"); Zwischenupdates |
| User ist technisch versiert | Fachsprache nutzen; auf Augenhöhe kommunizieren |
| User ist nicht technisch versiert | Sehr einfache Sprache; Remote-Support; Screenshots |

**Professionelle Standards:**
- Keine abwertenden Kommentare ("Das ist doch einfach").
- Keine Schuldzuweisung ("Sie haben das falsch gemacht").
- Lösungsorientiert bleiben.
- Bei Unwissenheit: "Das weiß ich nicht, aber ich finde es heraus."

## 3. Praxis-Übung im Homelab

Ziel: Kommunikationsskripte anwenden (Rollenspiel).

Schritte:
1. Partner (oder selbst) spielt User mit verschiedenen Profilen:
   a) Frustrierter User (PC langsam).
   b) Nicht-technischer User (Outlook startet nicht).
   c) Technisch versierter User (Netzwerkproblem).
2. Supporter nutzt Skripte aus Abschnitt 2.
3. Bewertung: Empathie? Klare Sprache? User geführt? Dokumentiert?

**Erwartetes Ergebnis:** Skripte angewendet; Kommunikation professionell.

## 4. Berühmte Fehler + Lösungen

**Fehler 1: "Zu viele Anweisungen auf einmal"**
- Symptom: User verwirrt; macht Fehler.
- Ursache: Supporter gibt 5 Schritte auf einmal.
- Diagnose: User reagiert nicht oder falsch.
- Lösung: Schritt-für-Schritt; nach jedem Schritt bestätigen.
- Prävention: Skripte nutzen; Pausen.

**Fehler 2: "User nicht bestätigen lassen"**
- Symptom: Supporter denkt, Schritt ist erledigt, aber User hat etwas anderes gemacht.
- Ursache: Keine Bestätigung.
- Diagnose: Ergebnis stimmt nicht.
- Lösung: "Was sehen Sie jetzt?" nach jedem Schritt.
- Prävention: Bestätigung als Pflicht.

**Fehler 3: "Abwertende Kommentare"**
- Symptom: User fühlt sich dumm; Eskalation an Management.
- Ursache: Supporter sagt "Das ist doch einfach" oder "Haben Sie das nicht gesehen?".
- Diagnose: User-Feedback.
- Lösung: Entschuldigen; professionell weitermachen.
- Prävention: Schulung; Empathie-Training.

**Fehler 4: "Bei Unwissenheit bluffen"**
- Symptom: Falsche Lösung; Vertrauensverlust.
- Ursache: Supporter erfindet Antwort statt zuzugeben, dass er es nicht weiß.
- Diagnose: Lösung funktioniert nicht.
- Lösung: Ehrlich sein ("Das weiß ich nicht, aber ich finde es heraus"); eskalieren.
- Prävention: Kultur der Ehrlichkeit; Wissensdatenbank nutzen.

## Ticket-Szenario zum Selbstlösen

**Ticket #9003:** "User (frustriert, nicht-technisch): 'Ich habe schon drei Mal angerufen und niemand kann mir helfen! Mein Outlook startet nicht und ich habe eine wichtige E-Mail zu senden!'"

**Lösung (aufklappbar):**
1. Empathie: "Ich verstehe Ihre Frustration, das ist wirklich ärgerlich. Lassen Sie uns das jetzt gemeinsam lösen."
2. Identität prüfen; Ticket-Historie prüfen (was wurde versucht?).
3. Einfache Sprache: "Ich werde jetzt Outlook im sicheren Modus starten. Das ist ein spezieller Modus, der Probleme beheben kann."
4. Schritt-für-Schritt führen; bestätigen lassen.
5. Wenn gelöst: "Outlook startet jetzt. Können Sie die E-Mail senden?"
6. Abschluss: "Das Problem ist gelöst. Ihre Ticket-Nummer ist X. Bei weiteren Fragen erreichen Sie uns unter Y."
7. Dokumentieren; ggf. KB-Artikel erstellen.
