# Modul 1 – Lektion 3: Kommunikation mit Usern

## 1. Lernziele
- Du kennst die Grundregeln der User-Kommunikation im Support.
- Du kannst aktives Zuhören anwenden.
- Du kannst Informationen strukturiert erfragen.
- Du kannst schwierige Situationen (frustrierte User) deeskalieren.

## 2. Theorie kompakt

**Grundregeln der Support-Kommunikation:**
1. **Begrüßen und vorstellen:** "Guten Tag, hier ist [Name] vom IT-Support. Wie kann ich helfen?"
2. **Zuhören:** User aussprechen lassen, nicht unterbrechen.
3. **Empathie zeigen:** "Ich verstehe, dass das frustrierend ist. Lassen Sie uns das gemeinsam lösen."
4. **Klare Sprache:** Kein Jargon; Fachbegriffe erklären. "Ich starte jetzt den Druckdienst neu" statt "Ich restarte den Spooler".
5. **Schritt-für-Schritt führen:** User durch Aktionen leiten ("Klicken Sie bitte auf Start...").
6. **Bestätigen:** "Haben Sie das gesehen? Was zeigt Ihr Bildschirm?"
7. **Zusammenfassen:** "Also das Problem ist X, wir haben Y versucht, nächster Schritt Z."
8. **Verabschieden:** Lösung bestätigen, Ticket-Nummer nennen, Rückfrage anbieten.

**Aktives Zuhören (Techniken):**
- **Paraphrasieren:** "Wenn ich Sie richtig verstehe, startet Outlook nicht nach dem Update?"
- **Nachfragen:** "Seit wann genau? Nur bei Ihnen oder auch bei Kollegen?"
- **Zusammenfassen:** "Zusammenfassend: X, Y, Z. Stimmt das?"
- **Pausen:** Stille aushalten, User denkt nach.

**Informationen strukturiert erfragen (W-Fragen):**
- **Was?** Symptom, Fehlermeldung (exakter Wortlaut).
- **Wann?** Seit wann, nach welcher Änderung.
- **Wo?** Welcher PC, Standort, Netzwerk.
- **Wer?** Betroffener User, Anzahl betroffener User.
- **Wie?** Schritte zur Reproduktion.

**Remote-Support-Kommunikation:**
- Vor Remote-Zugriff: User um Erlaubnis bitten ("Darf ich auf Ihren Bildschirm zugreifen?").
- User informieren, was man tut ("Ich öffne jetzt die Einstellungen").
- User nicht allein lassen (nicht einfach übernehmen ohne Erklärung).
- Nach Remote: Zusammenfassung + Ticket-Nummer.

**Deeskalation (frustrierte User):**
- Nicht persönlich nehmen.
- Anerkennen: "Ich verstehe Ihre Frustration."
- Lösungsorientiert: "Lassen Sie uns das jetzt lösen."
- Nicht streiten, nicht unterbrechen.
- Wenn nötig: Pause, Kollege übernehmen, Vorgesetzten informieren.
- Dokumentieren (User-Verhalten, Maßnahmen).

**E-Mail-Kommunikation:**
- Klare Betreffzeile (Ticket-Nummer + Kurzbeschreibung).
- Professionelle Anrede/Verabschiedung.
- Zusammenfassung des Problems + Lösung + nächste Schritte.
- Keine sensiblen Daten (Passwörter).
- Antwortzeit einhalten (SLA).

**Telefon-Etikette:**
- Innerhalb von 3 Klingeln abnehmen.
- Name + Abteilung nennen.
- Bei Weiterleitung: User informieren.
- Halten: "Darf ich Sie kurz halten?" → max. 1-2 Min, dann zurückmelden.
- Rückruf versprechen nur, wenn eingehalten.

## 3. Praxis-Übung im Homelab

Ziel: Ein Support-Gespräch simulieren (Rollenspiel).

Schritte:
1. Partner (oder selbst) spielt frustrierten User: "Mein PC ist schon wieder abgestürzt, das ist der dritte Mal diese Woche!"
2. Als Supporter: Begrüßung, Empathie, Informationen erfragen (W-Fragen), Lösung vorschlagen.
3. Dokumentiere das Gespräch (Notizen): Symptom, Schritte, Ergebnis.
4. Bewerte dich selbst: Habe ich zugehört? Klar gesprochen? Empathie gezeigt? Dokumentiert?

**Erwartetes Ergebnis:** Gespräch strukturiert geführt; alle relevanten Informationen gesammelt; User informiert.

## 4. Berühmte Fehler + Lösungen

**Fehler 1: "Supporter spricht in Fachjargon"**
- Symptom: User versteht nicht, was zu tun ist; frustriert.
- Ursache: Supporter nutzt technische Begriffe ohne Erklärung.
- Diagnose: User fragt nach oder macht nichts.
- Lösung: Einfache Sprache; Fachbegriffe erklären; Schritt-für-Schritt.
- Prävention: Schulung; Feedback von Usern; Checklisten.

**Fehler 2: "User wird unterbrochen / nicht angehört"**
- Symptom: User wiederholt sich, wird ungeduldig.
- Ursache: Supporter unterbricht, um schnell zur Lösung zu kommen.
- Diagnose: Gesprächsqualität.
- Lösung: Aktives Zuhören; User aussprechen lassen; dann zusammenfassen.
- Prävention: Schulung; Quality Monitoring (Call-Reviews).

**Fehler 3: "Remote-Zugriff ohne Erlaubnis"**
- Symptom: User erschrocken, fühlt sich überwacht; Beschwerde.
- Ursache: Supporter übernimmt Bildschirm ohne Vorwarnung.
- Diagnose: User-Feedback.
- Lösung: Immer um Erlaubnis bitten; erklären, was man tut.
- Prävention: Prozess-Standard; Schulung.

**Fehler 4: "Rückruf versprochen, aber nicht eingehalten"**
- Symptom: User verliert Vertrauen; eskaliert an Management.
- Ursache: Supporter überlastet, vergisst Rückruf.
- Diagnose: Ticket-Status prüfen.
- Lösung: Ehrlich entschuldigen; sofort zurückrufen; Ticket aktualisieren.
- Prävention: Rückruf-Tickets mit Reminder; realistische Versprechen; Team-Koordination.

## Ticket-Szenario zum Selbstlösen

**Ticket #2003:** "User (frustriert): 'Das ist jetzt schon das fünfte Mal, dass mein VPN nicht funktioniert! Ich kann nicht arbeiten!' Du bist Level 1."

**Lösung (aufklappbar):**
1. Begrüßung + Empathie: "Ich verstehe Ihre Frustration, das ist wirklich ärgerlich. Lassen Sie uns das jetzt lösen."
2. Informationen sammeln (W-Fragen): Fehlermeldung? Seit wann? Welches VPN? Andere User betroffen?
3. Ticket anlegen (Incident, Priorität nach Impact/Urgency).
4. Level-1-Versuche: VPN-Client neu starten, Netzwerk, Credentials, Zertifikat prüfen.
5. Falls gelöst: dokumentieren, schließen, User informieren.
6. Falls nicht: Eskalation an Level 2 mit Doku; User über Status informieren; Rückruf versprechen (und einhalten!).
7. Prävention: Wiederkehrendes Problem → Problem-Ticket erstellen (Root Cause).
