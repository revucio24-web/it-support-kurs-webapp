# Modul 9 – Lektion 1: Ereignisanzeige und Systemüberwachung

## 1. Lernziele
- Du kannst die Ereignisanzeige (Event Viewer) professionell nutzen.
- Du kannst benutzerdefinierte Ansichten erstellen.
- Du kannst wichtige Event-IDs interpretieren.
- Du kannst Systemüberwachung mit Performance Monitor durchführen.

## 2. Theorie kompakt

**Ereignisanzeige (eventvwr.msc):**
- Zentrales Tool für System-/Anwendungs-/Sicherheits-Logs.
- **Windows-Protokolle:** Anwendung, Sicherheit, Setup, System, Weitergeleitete Ereignisse.
- **Anwendungs- und Dienstprotokolle:** Spezifische Logs (z. B. Microsoft-Windows-PowerShell/Operational, Microsoft-Windows-TaskScheduler).

**Benutzerdefinierte Ansichten:**
- Ansicht → Benutzerdefinierte Ansichten erstellen → Filter nach Event-Level, Quelle, Event-ID, Zeitraum.
- Speichern für wiederholte Nutzung.

**Wichtige Event-IDs:**

| Event-ID | Quelle | Bedeutung |
|---|---|---|
| 41 | Kernel-Power | Unerwarteter Neustart/Absturz |
| 6008 | EventLog | Unerwartetes Herunterfahren |
| 1001 | BugCheck | Bluescreen (BSOD) mit Stop-Code |
| 4624 | Security | Erfolgreiche Anmeldung |
| 4625 | Security | Fehlgeschlagene Anmeldung |
| 4720 | Security | Benutzerkonto erstellt |
| 4726 | Security | Benutzerkonto gelöscht |
| 7001 | Service Control Manager | Dienst-Startfehler |
| 7009 | Service Control Manager | Timeout beim Dienst-Start |
| 1000 | Application Error | Anwendung abgestürzt |
| 1002 | Application Hang | Anwendung reagiert nicht |

**Performance Monitor (perfmon.msc):**
- Echtzeit-Überwachung von CPU, RAM, Disk, Netzwerk.
- **Leistungsindikatoren (Counters):** z. B. Processor\% Processor Time, Memory\Available MBytes, PhysicalDisk\% Disk Time.
- **Daten-Collector-Sets:** Aufzeichnung über Zeitraum (für Trend-Analyse).
- **Berichte:** Systemdiagnose, Systemleistung.

**Resource Monitor (resmon.exe):**
- Detaillierte Echtzeit-Analyse: CPU, Memory, Disk, Network.
- Pro Prozess: welche Dateien/Dienste nutzen Ressourcen.
- Nützlich für: "Welcher Prozess nutzt 100% Disk?"

**Reliability Monitor (perfmon /rel):**
- Grafische Darstellung von Systemstabilität über Zeit.
- Zeigt Abstürze, Updates, Fehler.
- Nützlich für: "Wann hat das Problem begonnen?"

## 3. Praxis-Übung im Homelab

Ziel: Ereignisanzeige und Performance Monitor nutzen.

Schritte:
1. `eventvwr.msc` → System-Log → Filter: Event-Level "Fehler" und "Warnung" (letzte 24 h).
2. Benutzerdefinierte Ansicht erstellen: Name "Kritische Fehler", Filter: Level Critical+Error, Quelle: alle, Zeitraum: letzte 7 Tage.
3. `perfmon.msc` → Leistungsüberwachung → Indikatoren hinzufügen: Processor\% Processor Time, Memory\Available MBytes, PhysicalDisk\% Disk Time.
4. Last erzeugen (z. B. `stress`-Tool oder Prime95) → Indikatoren beobachten.
5. `resmon.exe` → Disk-Tab → welcher Prozess nutzt Disk?
6. `perfmon /rel` → Reliability Monitor → Systemstabilität prüfen.

**Erwartetes Ergebnis:** Logs gefiltert; Performance-Indikatoren verstanden; keine kritischen Fehler.

## 4. Berühmte Fehler + Lösungen

**Fehler 1: "Zu viele Events – relevante nicht findbar"**
- Symptom: Tausende Events; Übersicht verloren.
- Ursache: Kein Filter; zu breite Ansicht.
- Diagnose: Filter setzen.
- Lösung: Benutzerdefinierte Ansicht erstellen; nach Event-ID filtern.
- Prävention: Regelmäßige Log-Reviews; Alerts.

**Fehler 2: "Event-ID 41 (Kernel-Power) – unerwarteter Neustart"**
- Symptom: PC startet unerwartet neu; Event-ID 41 im Log.
- Ursache: Stromausfall, Überhitzung, Hardware-Defekt, Treiber.
- Diagnose: Weitere Events (6008, 1001) prüfen; Temperatur; PSU.
- Lösung: Hardware prüfen; Treiber aktualisieren; PSU ersetzen.
- Prävention: Temperatur-Monitoring; USV; regelmäßige Hardware-Checks.

**Fehler 3: "Performance Monitor zeigt 100% Disk – System langsam"**
- Symptom: System träge; Disk-Auslastung bei 100%.
- Ursache: Defekte Festplatte; zu wenig RAM (Paging); Antivirus-Scan.
- Diagnose: `resmon` → Disk-Tab → welcher Prozess?
- Lösung: SMART prüfen (CrystalDiskInfo); RAM erhöhen; Antivirus-Ausschlüsse.
- Prävention: Regelmäßige SMART-Checks; RAM-Upgrade.

**Fehler 4: "Reliability Monitor zeigt Absturz-Serie"**
- Symptom: Mehrere Abstürze in kurzer Zeit.
- Ursache: Treiber, Hardware, Update.
- Diagnose: Reliability Monitor → Details (welche Anwendung?).
- Lösung: Treiber aktualisieren; Hardware prüfen; Update rückgängig machen.
- Prävention: Regelmäßige Updates; Hardware-Monitoring.

## Ticket-Szenario zum Selbstlösen

**Ticket #10001:** "User: 'Mein PC startet seit gestern unerwartet neu. Ich verliere meine Arbeit.'"

**Lösung (aufklappbar):**
1. Event Viewer → System-Log → Event-ID 41 (Kernel-Power) suchen → Zeitstempel.
2. Weitere Events: 6008 (unerwartetes Herunterfahren), 1001 (BSOD).
3. Temperatur prüfen (HWiNFO) → Überhitzung?
4. SMART prüfen (CrystalDiskInfo) → Festplatte?
5. PSU prüfen (Wattage ausreichend?).
6. Treiber aktualisieren (GPU, Chipsatz).
7. Windows Update prüfen (letzte Updates).
8. Dokumentieren; User informieren.
