# Modul 11 – Lektion 2: Gruppenrichtlinien (GPO)

## 1. Lernziele
- Du kannst erklären, was GPOs sind und wie sie angewendet werden.
- Du kannst GPOs erstellen, verknüpfen und verwalten (GPMC).
- Du kannst die GPO-Verarbeitungsreihenfolge (LSDOU) erklären.
- Du kannst GPO-Probleme diagnostizieren.

## 2. Theorie kompakt

**GPO (Group Policy Object):** Sammlung von Einstellungen, die auf User/Computer in AD angewendet werden. Steuert Sicherheit, Desktop, Software, Skripte, etc.

**GPO-Verwaltung:**
- **GPMC (Group Policy Management Console):** `gpmc.msc` – GPOs erstellen, bearbeiten, verknüpfen, sichern.
- **GPO-Editor:** `gpedit.msc` – einzelne GPO bearbeiten (Computer- und User-Konfiguration).
- **GPO-Speicher:** SYSVOL-Share auf DC (`\\domain\SYSVOL\domain\Policies\`).

**GPO-Struktur:**
- **Computer Configuration:** Einstellungen für Computer (Registry, Software, Skripte, Sicherheit).
- **User Configuration:** Einstellungen für User (Desktop, Software, Skripte, Ordnerumleitung).

**GPO-Verarbeitungsreihenfolge (LSDOU):**
1. **L**ocal (lokale GPO auf dem PC).
2. **S**ite (GPOs der Site).
3. **D**omain (GPOs der Domain).
4. **OU (Organizational Unit)** (GPOs der OU, von oben nach unten).
- Spätere GPOs überschreiben frühere (bei Konflikt).
- **Enforced (Erzwingen):** GPO wird nicht überschrieben (auch von späteren).
- **Block Inheritance (Vererbung blockieren):** OU ignoriert übergeordnete GPOs (außer Enforced).

**GPO-Aktualisierung:**
- Automatisch: alle 90 Min (±30 Min) + beim Boot/Anmeldung.
- Manuell: `gpupdate /force` (sofortige Aktualisierung).

**Wichtige GPO-Einstellungen:**
- **Passwort-Richtlinie:** Mindestlänge, Komplexität, Ablauf, Sperre.
- **Kontosperrung:** Anzahl Versuche, Sperdauer.
- **Desktop-Einstellungen:** Hintergrund, Taskleiste, Startmenü.
- **Software-Installation:** MSI-Pakete bereitstellen.
- **Skripte:** Logon/Logoff, Startup/Shutdown.
- **Ordnerumleitung:** Dokumente, Desktop auf Server umleiten.
- **Sicherheitsoptionen:** UAC, Firewall, BitLocker.

**GPO-Diagnose:**
- `gpresult /r` – angewendete GPOs anzeigen (CMD).
- `gpresult /h C:\gpreport.html` – HTML-Bericht.
- `rsop.msc` – Resultant Set of Policy (grafisch).
- Event Viewer → GroupPolicy-Log.

## 3. Praxis-Übung im Homelab

Ziel: GPO erstellen und verknüpfen.

Schritte (in DC-VM):
1. `gpmc.msc` öffnen.
2. Rechtsklick auf "Group Policy Objects" → "Neu" → Name "Lab-Password-Policy".
3. GPO bearbeiten: Rechtsklick → "Bearbeiten" → Computer Configuration → Policies → Windows Settings → Security Settings → Account Policies → Password Policy.
4. Einstellungen: Mindestpasswortlänge 12, Komplexität aktivieren, Max. Alter 90 Tage.
5. GPO verknüpfen: Rechtsklick auf Domain `lab.local` → "Vorhandenes GPO verknüpfen" → "Lab-Password-Policy".
6. Client-VM: `gpupdate /force` → Passwort-Richtlinie prüfen (`net accounts`).
7. `gpresult /r` → angewendete GPOs prüfen.

**Erwartetes Ergebnis:** GPO erstellt und verknüpft; Passwort-Richtlinie auf Client angewendet.

## 4. Berühmte Fehler + Lösungen

**Fehler 1: "GPO wird nicht angewendet"**
- Symptom: Einstellung nicht wirksam; `gpresult /r` zeigt GPO nicht.
- Ursache: GPO nicht verknüpft; Sicherheitsfilterung (keine Berechtigung); WMI-Filter; Block Inheritance.
- Diagnose: `gpresult /r`; GPMC → Verknüpfung prüfen; Sicherheitsfilterung prüfen.
- Lösung: GPO verknüpfen; Berechtigung hinzufügen (Authenticated Users); WMI-Filter prüfen.
- Prävention: Vor Verknüpfung prüfen; Test-OU nutzen.

**Fehler 2: "GPO-Konflikt – falsche Einstellung gewinnt"**
- Symptom: Erwartete Einstellung nicht wirksam; andere GPO überschreibt.
- Ursache: LSDOU-Reihenfolge; spätere GPO überschreibt.
- Diagnose: `gpresult /r` → Reihenfolge prüfen; `rsop.msc`.
- Lösung: Enforced setzen; oder GPO-Reihenfolge ändern; oder Konflikt auflösen.
- Prävention: GPO-Design planen; Enforced sparsam nutzen.

**Fehler 3: "GPO-Verarbeitung langsam – Boot/Anmeldung verzögert"**
- Symptom: Client braucht lange zum Booten/Anmelden.
- Ursache: Zu viele GPOs; große Skripte; langsame Netzwerkverbindung.
- Diagnose: `gpresult /h` → Verarbeitungszeit; Event Viewer (GroupPolicy).
- Lösung: GPOs konsolidieren; Skripte optimieren; WMI-Filter prüfen.
- Prävention: GPO-Anzahl minimieren; regelmäßige Review.

**Fehler 4: "GPO nicht repliziert – SYSVOL-Problem"**
- Symptom: GPO auf einem DC vorhanden, auf anderem nicht.
- Ursache: SYSVOL-Replikation fehlgeschlagen (DFSR).
- Diagnose: `repadmin /showrepl`; Event Viewer (DFSR).
- Lösung: Replikation erzwingen; DFSR-Reparatur.
- Prävention: Replikations-Monitoring; SYSVOL-Backup.

## Ticket-Szenario zum Selbstlösen

**Ticket #12002:** "User: 'Mein Desktop-Hintergrund ändert sich nicht, obwohl IT gesagt hat, dass sie eine neue Richtlinie ausgerollt haben.'"

**Lösung (aufklappbar):**
1. `gpresult /r` → ist die GPO angewendet?
2. Wenn nicht: GPO-Verknüpfung prüfen (GPMC); Sicherheitsfilterung (Authenticated Users?).
3. `gpupdate /force` → GPO aktualisieren.
4. Wenn immer noch nicht: Block Inheritance? WMI-Filter?
5. Event Viewer → GroupPolicy-Log → Fehler?
6. GPO-Einstellung prüfen (richtiger Pfad?).
7. Dokumentieren.
